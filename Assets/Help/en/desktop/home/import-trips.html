Importing a broker's trips

How to load a broker's CSV file, and what to do with the trips that do not go in.

how-toNew in 1.6.1

Importing puts the trips a broker sent you in a file into the system, without typing any of them by hand.

When you need it#

The broker has sent you tomorrow's CSV and those trips have to be on the Home tab before anyone starts routing.

The steps#

  1. On Home, press the import button — the database icon with an arrow.
  2. Under "Seleccionar Funding Source", choose the broker the file belongs to.
  3. Press "SELECCIONAR CSV" and choose the file.
  4. Wait. The bar shows "Locating N of M addresses…" first and then "Importing N of M trips…". A file of four hundred trips takes a little over a minute.
  5. Read the message when it finishes: it says how many trips went in as new and how many were updated.
  6. Press "VOLVER A INICIO".

The broker you choose decides what is required of the driver

The funding source you choose is not a label: it decides what will be required of the driver on every trip in the file — signatures, odometer, barcode scan. If you choose the wrong one, the screen warns you when the file's layout does not match the broker, but between two brokers that share a layout it cannot tell.

What can go wrong#

"Trips not imported", with a list of TripIds. Those trips are not in the system. Below, in the table, each one has its reason in the Status and Reason columns. Find them in the original file by that TripId, correct what the reason says, and import the same file again.

The reasons you will see:

  • The address could not be located on the map. The street, city, state or ZIP is wrong in the file.
  • Not a mobility type this system knows. The type column carries a new value. Correct it in the file, or add the space type under Admin.
  • The patient cannot be identified. The row carries neither a rider id nor a phone number. A name alone is not enough: two patients who share one would end up as a single record, and each would start seeing the other's trips.
  • An active trip already exists. Same patient, same day, same two addresses and same pickup window.

"Import stopped". The server stopped answering partway through the file. The trips that had already gone in are stored. Wait a couple of minutes and import the same whole file again.

Importing again is safe

Trips are recognised by the broker's own identifier. A trip that already went in is updated, never duplicated. So when in doubt, import again: you will not send two vehicles.

A trip you cancelled earlier stays cancelled even if it comes back in the file. Its details are refreshed, but it does not reinstate itself.
